Once you have agreed the SEO scope in a website quote, decide what evidence you will receive when the work is finished. “We submitted the site to search engines” tells you little about which pages changed or what was done.

Your hospital does not need to read every line of development code. A record connecting each checked URL with the changes and verification results gives your team a practical way to review the work.

Start with a list of the pages to check

Checking only the homepage can miss problems on service or medical team pages. First collect the URLs covered by the agreed review.

Select the pages the hospital actually needs, such as services, medical team profiles, first-visit booking, directions and information in other languages. Check whether people can find each page through the menu and whether a shared link opens the same content.

For a redesign that changes page addresses, list old and new URLs side by side. Share that list when commissioning the search review so missing pages are easier to identify.

Check the content search engines actually read

Seeing a service description beside a photograph does not prove that a search engine has read the same information. Check whether the explanation exists only in an image, is supplied as page text or fails to load properly.

Google describes its process for crawling, rendering and indexing JavaScript pages. Rather than judging the site by the name of its technology, check whether the rendered page contains the necessary explanations and links.

When receiving Google Search Console URL Inspection records, distinguish the indexed version from a test of the current page. A successful live test does not also mean the page is indexed. Ask the agency to state the check date and which result is being reported.

Keep public information pages separate from private screens containing patient information. Define the review scope so access restrictions are not changed across the whole site simply in the name of SEO.

Make sure titles, descriptions and page content agree

A page title should identify the service or guidance being offered. Repeating only the hospital name on every page does not explain what makes each one useful. Compare the description with the actual text as well.

Your hospital's reviewer should check facts such as doctor names, services, location, opening hours and the languages available for consultations. The title and description shown in search may differ from the ones you supplied, so review the actual search appearance separately.

If structured data has been added, ask which information it represents on which pages. Google says it should match the visible content. When medical team details or opening hours change, check both the page text and the associated data.

Separate changes made from work still outstanding

Ask for the review records to include:

  • The URLs checked and the check dates
  • Problems found and changes made
  • The tools used, results and screens reviewed
  • Information that needs the hospital's review
  • Items not yet verified and the follow-up schedule

State whether the agency reviewed every page or a sample. Record how representative pages were selected and what was excluded so a single page's result is not mistaken for a site-wide finding.

Also distinguish completed work from items waiting for further search-engine processing. An access-setting fix may be finished while the page's indexing still needs a later check.

Check actual search visibility and inquiries separately after launch

Google also recommends established SEO principles for AI Overviews and AI Mode. After checking public-page access and content, observe how the hospital's information actually appears in search results and AI answers.

Record AI answers with the AI service used, question, language and date checked. Use the same criteria when checking again so changes are easier to compare. Review the website's inquiry function separately from the search records. Appearing in search and successfully receiving a form submission are different checks.
