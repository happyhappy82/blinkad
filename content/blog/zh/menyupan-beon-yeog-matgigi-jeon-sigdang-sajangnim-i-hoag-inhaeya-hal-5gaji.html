准备接待外国顾客，经营者常会考虑英文、日文或中文菜单。尤其当门店已收到相关询问时，一份读得懂的菜单，能帮助顾客先了解提供什么、怎样点餐。

不过，把文件交给翻译人员以前，门店也有一些资料要先确认。菜名译得自然很重要，顾客还需要知道价格、份量、配料和点餐条件。

我们是BlinkAd。整理餐厅线上信息时，我们建议把菜单和照片、实际出品与价格放在一起核对，而不是只检查每个词有没有翻出来。

委托翻译前，先整理原始菜单

韩文原稿中有不清楚的地方，翻译人员也容易理解错。可以先找出下面这些问题，再交付资料；需要选择语言顺序时，可参阅多语言菜单准备到什么程度。

  • 招牌菜没有明确标出。
  • 价格与点餐单位分散，难以对应。
  • 辣度、肉类或海鲜种类没有核实。
  • 照片中的菜与菜名或实际供应内容不同。
  • 线上仍在展示旧菜单照片。

1. 先分出需要重点介绍的菜

可以先挑约五道招牌菜，数量按门店调整。完整菜单仍需清楚说明，但重点介绍的菜可以配更具体的图片和描述，不必每一道都占相同篇幅。

选择时，除了销售情况，也可以考虑是否能如实体现本店特色、照片是否与实际一致，以及员工能否准确解释内容。以下是不同业态可以整理的例子，并不是每家店必须提供的菜单。

  • 烤肉店：猪五花、猪颈肉、排骨、韩牛拼盘、大酱汤等，按实际供应选择。
  • 韩餐厅：拌饭、烤肉、泡菜汤、辣炒猪肉、海鲜煎饼等。
  • 咖啡馆：招牌咖啡、非咖啡饮品、甜点与季节商品。
  • 酒吧：招牌小食、套餐、生啤、传统酒与Highball等。
交给翻译人员时，除了完整菜单，也说明哪几项需要重点展示，以及这些选择基于哪些真实资料。

2. 保留菜名，再补一句说明

只把韩语发音写成拉丁字母，第一次见到的人未必能理解。可以保留菜名，再写菜品类型、主要配料与实际做法。下面的例子须与本店配方相符。

  • Kimchi Jjigae → Kimchi stew with pork and tofu（泡菜炖汤，含猪肉、豆腐时使用此说明）。
  • Bulgogi → Marinated grilled beef（腌制烤牛肉；做法不同应相应调整）。
  • Doenjang Jjigae → Soybean paste stew with tofu and vegetables（含豆腐、蔬菜的大酱汤，汤底和其他配料仍需核查）。
  • Samgyeopsal → Grilled pork belly（烤猪五花肉）。
菜名、配料和烹调方式可以一起帮助顾客判断，但简短描述不等于完整配方。不能因为英文写了蔬菜或豆腐，就推断这道菜一定适合素食或没有特定过敏原。

3. 价格、份量和起点数量，分别写

例如，两份起点、每人需点一项、米饭另计，或肉类以150克为一份，都是需要翻译的条件。这些只是写法例子，应按本店实际规则和价格替换，不能当成所有韩国餐厅的规定。

交付以前，可以把下面几项单独列清。

  • 价格是每份、每人还是每桌；重量或份量是多少。
  • 是否有最低点餐数量；“两份起点”与“供两人食用”分别写。
  • 米饭、小菜、酱料与饮品是否包含，另购项目怎样计价。
  • 哪些菜可外带，是否有实际包装费用。
  • 最后点餐时间和休息时段。
额外费用和点餐条件应在顾客决定前说明，并与员工回答一致。不需要按国籍推断谁更在意价格，所有顾客都值得得到清楚的信息。

4. 辣度与配料，先向厨房确认

翻译人员可以把说明写清楚，却不能凭菜名判断真实配方。先确认汤底、酱料、配料与可调整范围，再准备下面这类标签；它们不构成完整的过敏原清单。

  • Spicy / Mild / Not spicy（辣、较轻辣度、不辣，按实际配方说明）。
  • Contains pork（含猪肉，涉及饮食限制时也需核实其他来源）。
  • Contains beef（含牛肉）。
  • Contains seafood（含海鲜，应明确具体种类）。
  • Contains shellfish（含贝类或甲壳类时，应说明实际种类，不含糊合并）。
  • Contains nuts（含坚果，需具体核实；花生与树坚果也应分别确认）。
  • Vegetarian option available（确有符合对应要求的素食选项时使用，不等于没有过敏原）。
食品标准局的配料与过敏沟通指南提醒，配方变化和交叉接触也需要考虑。这里参考其沟通方法，不把英国法规直接用于韩国门店。厨房无法确认时，要明确告知，不以“可以少辣”或“看起来没有肉”代替核查，也不保证绝对无过敏风险。

5. 店内译稿与线上菜单，一起核对

顾客可能先从地图或商家页面看菜单，再到店点餐。若线上还是旧价，员工就需要反复解释。建议把店内菜单和实际使用的线上入口一起整理。

Google菜单编辑器面向餐饮类商家，可列菜单项、说明和价格，但受账号与来源等条件影响。部分功能可用照片或PDF配合AI创建菜单，生成后仍需复核，不能假定所有账号都有同样功能或每一项识别都准确。

  • 提供清楚、仍然适用的菜单照片。
  • 对照招牌菜照片、菜名与实际出品。
  • 核对营业时间、休息时段和最后点餐时间。
  • 按需要回应外语评价中的具体疑问。
  • 检查旧价格照片的来源；本店可管理的更新，他人上传的按平台规则处理。
商家不能承诺任意删除所有用户照片，更新也可能需要时间才显示。先补充准确的现行信息，再处理其他来源的问题，不把菜单上传完成等同于排名改善。

交付翻译时，把这些资料一起备好

不只传一张菜单图片，还可以提供一份已经核对的资料，减少反复追问。

  • 清楚、可读取的韩文菜单原稿。
  • 需要重点展示的约五道菜，数量按实际调整。
  • 与菜品一一对应的真实照片。
  • 各菜主要配料，含汤底与酱料资料。
  • 辣度与厨房实际可调整的范围。
  • 已核实的过敏信息、交叉接触情况及无法确认的部分。
  • 价格、份量、起点数量与额外费用。
  • 门店定位、希望使用的语言与实际顾客询问。
资料改变以后，也要告诉负责翻译和线上更新的人。几种语言对照同一份确认过的菜单，以后改价或换菜时，也更容易同步更新。

收到译稿后，按实际点餐过程读一遍

除了词句顺不顺，也可以按顾客能否完成点餐来读一遍。涉及本店事实的内容，由了解菜单和厨房的人确认。

  • 不看照片，也能大致知道是什么菜。
  • 价格、份量和起点条件清楚。
  • 辣度、配料与过敏说明没有遗漏已知的重要信息。
  • 招牌菜容易找到，完整菜单也有清楚顺序。
  • 内容与本店实际使用的线上菜单相符。
这些项目有助于检查是否好用，但不能用“看起来可以点餐”替代专业词语、配方和条件复核。文字自然与信息准确，应当一起做好。

BlinkAd建议怎样安排？

菜单能让顾客了解本店卖什么、价格和点餐方式。与其先追求很多语言，可以先把一份真实、清楚的资料准备好，再检查顾客还有哪些问题。

之后让菜名、照片、价格、员工说明与线上信息保持一致。翻译可以帮助顾客理解门店，实际到店和销售变化仍需观察，不把翻译完成当成结果保证。

常见问题

只译英语，就够了吗？

按实际询问和阅读反馈决定。没有明确需求资料时，英语可以作为起点；已经有日语、简体或繁体需求的门店，也可优先准备对应版本。

可以先用翻译工具吗？

可以辅助起草，但菜名、配料、过敏信息、价格和点餐条件，需要由了解本店情况的人核对。语言通顺不代表配方已经确认。

翻译菜单后，外国顾客就会增加吗？

不能由翻译完成直接推断。还要看顾客能否找到菜单、线上信息是否准确，以及实际服务和需求。可以记录收到的询问和点餐反馈，再决定改哪里。

Google地图上，也需要放菜单吗？

若本店使用这个平台，可以按账号实际可用的菜单项、照片或入口提供资料，并与店内版本一致。展示方式和更新时间依平台条件确认。
