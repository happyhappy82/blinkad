# 병원 홈페이지 오픈 검수와 이후 관리, 어디까지 맡겨야 할까?

병원 홈페이지 오픈일이 정해지면 사진과 문구를 고치는 데 관심이 쏠립니다. 마지막 검수에서는 화면 밖의 일도 확인해야 합니다. 환자가 문의를 남겼을 때 직원이 받는지, 검색엔진이 페이지를 읽을 수 있는지, 다음 달 진료시간을 누가 바꿀지까지 정해져야 운영을 시작하기 편합니다. 검수표에는 확인할 결과를, 관리 계약에는 담당자와 지원 범위를 적어두세요.

## 공개, 색인, 실제 노출을 나눠 확인하세요

첫째는 공개 상태입니다. 관리자 로그인 없이 외부 휴대전화에서도 페이지가 열리는지 확인하세요. 진료 안내와 의료진 소개가 보이고, 메뉴와 전화 버튼이 작동하는지 살펴봅니다. 새 사이트를 준비하며 걸어 둔 검색 차단 설정의 해제 여부는 제작사에 확인받습니다.

둘째는 검색엔진의 색인 상태입니다. Google Search Console의 URL 검사에서 보는 색인 데이터는 Google이 마지막으로 처리한 페이지 기준입니다. 실시간 테스트는 현재 페이지를 가져와 검사하므로, 수정 직후에는 두 결과가 다를 수 있습니다. 실시간 테스트 통과만으로 색인이 보장되지는 않습니다. 검수 자료에는 검사한 주소와 확인일, 색인 데이터와 실시간 테스트 결과를 구분해 달라고 요청하세요. [Google URL 검사 안내](https://support.google.com/webmasters/answer/9012289)를 참고하세요.

셋째는 실제 검색 결과와 AI 답변에서의 노출입니다. 확인한 검색어나 질문, 날짜를 기록해 점검 결과를 남깁니다. Google의 AI 개요·AI 모드에 보조 링크로 표시되려면 페이지가 색인되고 검색 결과에 스니펫을 표시할 자격을 갖춰야 합니다. 요건을 갖춰도 노출은 보장되지 않습니다. 이 기준은 [Google AI 기능 안내](https://developers.google.com/search/docs/appearance/ai-features)의 설명입니다. ‘AI 검색 대응 완료’를 인수 기준으로 쓴다면, 접근 설정과 페이지 정보 점검인지, 노출 현황 보고까지 포함하는지 구체적으로 적어야 합니다.

## 문의는 완료 화면에서 접수함까지 확인하세요

문의 검수는 제출 버튼을 누르고 끝내지 마세요. 병원 직원과 함께 테스트용 연락처로 문의를 남긴 뒤, 실제로 확인할 관리자 화면이나 지정 이메일에 내용이 도착하는지 봅니다. 휴대전화에서 필수 항목 누락 안내와 중복 접수 여부도 확인합니다. 환자의 실제 상담 내용이나 민감한 정보를 테스트에 쓰지 마세요.

접수 알림을 받는 직원과 부재 시 확인할 사람, 접수함 접근 권한을 정해 두세요. 카카오 채널이나 외부 예약 서비스로 연결한다면 해당 서비스의 계정과 연결 목적지도 함께 확인하세요. 홈페이지 안의 문의 접수와 외부 서비스의 예약 확정 중 어디까지 제작사의 점검 범위인지 구분해야 합니다.

수정 요청에는 ‘문의가 안 된다’ 대신 접속 기기, 페이지, 발생 시각, 기대한 결과를 적습니다. 제작사에는 수정 내용과 재시험 결과를 같은 기록에 남겨 달라고 요청하세요. 접수 기능의 작동 여부와 이후 직원의 응대 속도는 담당자를 각각 정해 관리합니다.

## 오류 보수와 운영 변경의 범위를 적으세요

오픈 후 지원은 기간만 적어 두면 해석이 갈립니다. 합의한 기능이 작동하지 않는 오류의 수정, 병원 요청에 따른 문구 변경, 새 페이지 제작은 작업 성격이 다릅니다. 진료시간 변경이나 의료진 교체를 예로 들어 포함 여부와 별도 견적 기준을 확인하세요. 실제 요청 목록을 놓고 포함 여부를 정하면 모호함이 줄어듭니다.

계약서에는 지원 시작일과 종료일, 요청 창구, 응대 시간대, 장애 접수 후 첫 답변 기준을 남깁니다. 첫 답변과 복구 완료는 구별하고, 외부 예약 서비스 장애나 플랫폼 정책 변경처럼 제작사가 직접 해결하기 어려운 일의 연락 범위도 합의하세요. 검색 상태 점검과 정기 보고가 필요하다면 횟수와 대상 페이지를 별도 항목으로 정합니다.
