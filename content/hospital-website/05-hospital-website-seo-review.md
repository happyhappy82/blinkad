# 병원 홈페이지 SEO 검수, 실제 페이지에서 확인하는 항목

견적서에서 SEO 작업 범위를 확인했다면, 다음에는 완료 자료를 어떻게 받을지 정해야 합니다. “검색 등록을 해드렸다”는 설명만으로 어느 페이지에서 무엇이 달라졌는지 알기는 어렵습니다.

병원에서 개발 코드를 모두 읽을 필요는 없습니다. 점검한 주소와 수정한 내용, 확인 결과가 연결된 자료를 받으면 담당자도 작업을 검수할 수 있습니다.

## 주요 페이지 주소부터 목록으로 만드세요

첫 화면만 확인하면 진료 안내나 의료진 페이지의 문제를 놓칠 수 있습니다. 이번 계약에서 점검하기로 한 페이지 주소를 먼저 모읍니다.

진료 안내, 의료진 소개, 초진 예약, 오시는 길, 다국어 안내 등 실제 운영에 필요한 페이지를 고르세요. 메뉴에서 해당 페이지를 찾을 수 있는지, 주소를 전달했을 때 같은 내용이 열리는지도 확인합니다.

리뉴얼로 주소가 바뀌는 페이지는 기존 주소와 새 주소를 나란히 적습니다. 검색 점검을 맡길 때부터 그 목록을 공유해야 빠진 페이지를 확인하기 쉽습니다.

## 검색 서비스가 읽은 본문을 확인합니다

사진 옆에 진료 설명이 보인다고 검색 서비스도 같은 내용을 읽었다고 단정할 수는 없습니다. 이미지에만 들어간 설명인지, 본문 텍스트로 제공하는지, 내용을 불러오는 과정에 문제가 없는지 점검합니다.

Google은 자바스크립트 페이지를 수집·렌더링·색인하는 과정을 안내합니다. 사용하는 기술 이름보다 실제로 처리된 본문에 필요한 설명과 링크가 있는지 확인하세요.

Google Search Console의 URL 검사 자료를 받을 때는 검색에 등록된 페이지 정보와 현재 페이지 테스트를 구분합니다. 현재 페이지가 정상적으로 처리되더라도 검색에 등록됐다는 의미까지 갖는 것은 아닙니다. 자료에 확인 날짜와 어느 결과를 본 것인지 표시해달라고 요청하세요.

공개할 안내 페이지와 환자 정보가 있는 비공개 화면도 구분해야 합니다. SEO 점검을 이유로 모든 페이지의 접근 제한을 한꺼번에 바꾸지 않도록 범위를 정합니다.

## 제목·설명·본문이 같은 내용을 말하는지 봅니다

페이지 제목은 해당 진료나 안내를 구분할 수 있게 작성합니다. 모든 페이지에 병원 이름만 반복하기보다 무엇을 안내하는 페이지인지 드러나야 합니다. 설명문과 실제 본문도 맞춰보세요.

담당자는 의료진 이름, 진료 범위, 위치, 운영시간, 상담 가능 언어처럼 병원에서 확인할 사실을 검수합니다. 검색 결과에서 보이는 제목과 설명은 작성한 설정 그대로만 표시되는 것은 아니므로 실제 표시 내용도 따로 살펴봅니다.

구조화 데이터를 적용했다면 어떤 페이지의 어떤 정보를 표현했는지 받으세요. Google은 구조화 데이터가 화면 내용과 일치해야 한다고 안내합니다. 의료진이나 운영시간을 수정했다면 본문과 적용된 데이터도 함께 확인합니다.

## 보고서에는 수정 전후와 남은 일을 나눠 적습니다

검수 자료는 아래 항목으로 정리해달라고 요청할 수 있습니다.

- 점검한 페이지 주소와 확인 날짜
- 발견한 문제와 수정한 내용
- 사용한 도구, 확인한 결과와 화면
- 병원 검수가 필요한 정보
- 아직 확인하지 못한 항목과 후속 확인 일정

전체 페이지를 확인했는지 일부를 확인했는지도 적어야 합니다. 한 페이지의 결과를 사이트 전체에 적용한 것으로 오해하지 않도록 대표 페이지 선정 기준과 제외 범위를 남깁니다.

작업이 끝난 항목과 검색 서비스의 후속 처리를 기다리는 항목도 분리하세요. 접근 설정 수정은 완료했지만 검색 등록 상태는 다음에 확인해야 하는 경우가 있을 수 있습니다.
