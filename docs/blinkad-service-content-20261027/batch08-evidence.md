## O04 · llms.txt와 실제 페이지를 함께 확인

- 현재 제목: `GEO 마케팅 대행 결과, llms.txt와 실제 페이지를 함께 확인하세요`.
- 핵심 근거: [Google AI features and your website](https://developers.google.com/search/docs/appearance/ai-features). 10/27 웹 도구 재열람·직접GET200 확인.
- 문서가 다루는 범위는 **Google Search의 AI Overviews·AI Mode**다. 기존 SEO 원칙이 적용되고, 색인돼 스니펫 표시 자격이 있어야 지원 링크로 노출될 수 있지만 게재는 보장되지 않는다.
- 문서는 해당 기능에 등장하기 위해 새로운 기계가독 파일·AI 텍스트 파일·특수 마크업을 별도로 만들 필요가 없다고 안내한다. 따라서 **파일1개 납품 사실과 계약한 실제 페이지 변경·접근 확인은 나눠 검수**할 수 있다.
- 파일에 어떤 목적이 있는지, 실제로 바꾼 URL과 변경 전후·접근 검사·확인일·남은 작업이 무엇인지 살펴보는 예시가 본문 추가 가치다. llms.txt가 모든 AI에 무효·AI가 절대 읽지 않음·제작 업체가 사기라는 결론은 문서가 지지하지 않는다.
- [자사 AEO 안내](https://www.blinkad.kr/aeo)는 질문 진단, 웹사이트/스키마, 콘텐츠, 프로필·외부 정보, 반복 리포트 업무를 공개한다. 이 페이지의 제공 설명은 서비스 범위 자료이며 '이 작업을 하면 반드시 인용된다'는 검증 자료가 아니다. 공개 페이지에 있는 통계·상관수치·성과 시점을 새 사실처럼 승계하지 않는다.
- 기본 링크는 브리프의 `/aeo` 본문 UTM·`/contact` 상담 UTM을 유지한다. 예정 H04 주소를 새로 만들거나 모든 독자를 별도 기술 글로 돌리지 않는다.

## N04 · 원문을 대조해 보고서 주장을 인정·수정·확인불가로 남기기

기존 질문군 구분 주제는 예약6/7/11편과 직접 겹쳐 root가 교체하기로 했다. 새 제목은 **`GEO 보고서의 추천·인용, 원문에서도 그렇게 확인되나요?`**다. 정확 원문 근거와 교체 이유는 `remaining-dedup-audit.md`와 `historical-nv9-recovered.json`에 있다.

- 새 독자 결정: 질문군을 어떻게 설계할지보다, **보고서의 특정 추천·인용 주장이 실제 증거와 맞는지 판독하고 고칠 표현을 정한다.**
- 확인할 열: 보고서 주장 → 질문 원문 → 답변의 해당 문장 → 단순 언급/추천/링크 표시 → 출처 페이지의 지지 문장 → 검수 결과.
- 브랜드명을 넣은 질문은 첫 확인 항목으로만 둔다. '이름을 넣었으니 모두 무효'로 처리하지 말고 실제 질문·문장·주장한 성과를 맞춰 읽는다.
- 출처 링크가 있다고 그 링크가 모든 답변 주장을 뒷받침하는 것은 아니다. 출처에 브랜드명이 나오는 사실과 답변의 특정 비교·서비스 조건 주장을 지지하는지를 구분한다. 이는 **제안하는 증거 검수 방법**이며 공식 GEO 인증 점수나 특정 AI 서비스의 판정 규칙이 아니다.
- 예시를 쓸 때는 가상의 질문·답변·보고서 행임을 밝히고 수치를 꾸미지 않는다. 실제로 측정한 고객 보고서·실제 AI 추천을 발견한 것처럼 쓰지 않는다. 의료 효과·특정 병원 우열의 진위를 판정하는 글로 확장하지 않는다.
- 기존9는 질문 원문·분모·인용/언급 정의와 출처를 기록하라고 하지만, **인용 페이지의 특정 문장과 보고서 행을 대응시켜 수용/수정/확인불가로 처리하는 예시 감사**를 직접 제시하지 않았다. 이 구체적 새 판단을 빼면 다시 중복된다.
