# H03 집필 근거 — 기존 한국어 사이트에 병원 다국어 페이지 추가

확인일: **2026-10-27 KST**. 읽기 조사·집필 근거 정리만 수행했다. 완성 원고 작성, 홈페이지·플랫폼·Git 수정, 서버 설정·명령 실행은 하지 않았다.

## 글의 중심 판단

기존 한국어 홈페이지를 운영하면서 다국어 영역을 추가할 수 있는지, 가능하다면 기존 제작사·추가 제작사·병원 중 누가 어느 작업을 맡을지 판단하도록 돕는다. `한국어 홈페이지를 전부 다시 만들어야 하는가`라는 기존 글의 일반 판단을 반복하지 않고 **함께 운영할 때 바뀌는 경로·메뉴·배포·복구 범위**에 집중한다.

원고의 결론은 `모든 사이트에서 바로 가능하다`가 아니라 **현재 사이트의 운영 조건을 확인하고 바뀌는 범위와 담당부터 정하라**는 행동 권고다. Google 문서는 다국어 URL·검색 처리 원칙을 설명하며, 특정 병원 호스팅의 추가 제작 가능 여부를 대신 확인해주지 않는다.

## 공식 출처 4개

| ID | 공식 문서 | 확인할 부분 | 적용 범위 |
|---|---|---|---|
| G1 | [다국어·다지역 사이트 관리](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) | 언어별 독립 URL, 언어 선택 링크, 자동 언어 이동 주의, URL 구조별 장단점 | 다국어 영역 설계의 선택지를 설명. 특정 구조의 순위 우위나 모든 서버에서의 구현 가능성을 보장하지 않음 |
| G2 | [현지화된 페이지 버전 알리기](https://developers.google.com/search/docs/specialty/international/localized-versions) | hreflang 표시 방법, 대응 URL의 상호 연결, 다른 도메인의 언어 버전도 가능 | 언어별 진료 페이지 주소와 대응 관계를 정할 근거. 설정만으로 색인·올바른 노출을 보장하지 않음 |

| G4 | [Google 검색 기술 요구사항](https://developers.google.com/search/docs/essentials/technical) | Googlebot 접근, HTTP200, 색인 가능한 본문, 색인 비보장 | 공개 화면 확인과 검색 접근·색인 확인을 나눌 근거. 정상 접속·사이트맵 제출을 검색 색인 완료로 표현하지 않음 |

모두 10/27 Google 공식 원문을 읽어 확인했다. Google 검색의 원칙이며 ChatGPT·모든 AI 서비스의 작동 방식으로 일반화하지 않는다.

## 글에 쓸 핵심 사실 6개

1. **언어별로 접근할 수 있는 고유 주소를 정한다.** Google은 쿠키·브라우저 설정으로 한 주소의 언어만 바꾸는 방식보다 언어별 독립 URL을 권장한다. 예를 들어 `/en/`은 가능한 주소 예시이며 특정 병원의 실제 경로가 아니다. [G1]
2. **하위디렉토리·서브도메인 등은 운영 조건을 보고 고른다.** Google 문서는 여러 URL 구조의 장단점을 설명한다. 같은 도메인의 하위디렉토리만 무조건 검색에 유리하다고 결론내리지 않는다. 실제 기존 호스팅에서 추가 영역을 연결할 수 있는지는 별도 확인 사항이다. [G1]
3. **사용자가 언어를 선택할 수 있는 연결을 준비한다.** Google은 언어 버전 사이의 링크를 제시하고 추정 언어·위치에 따른 강제 자동 이동을 피하도록 안내한다. 원사이트 메뉴를 수정할 수 있는지, 어느 진료 페이지로 연결할지는 제작 담당이 확인할 작업이다. [G1]
4. **대응하는 언어 페이지 목록을 먼저 만든다.** `hreflang`을 쓴다면 서로 대응하는 URL을 올바르게 알리고 상호 참조해야 한다. 표시 방법은 HTML·HTTP 헤더·사이트맵 중 운영에 맞게 고를 수 있다. 대응 페이지가 없는데 있는 것처럼 주소를 만들지 않는다. [G2]
5. **페이지가 열린 것과 검색에 색인된 것은 다르다.** 공개 페이지의 정상 응답·Googlebot 접근·색인 가능한 본문을 확인해야 한다. 기술 조건을 충족해도 색인이 보장되지는 않는다. [G4]
6. **한국어 주소를 바꾼다면 언어 추가와 별도로 이전 계획을 세운다.** 기존 URL과 새 URL 대응, 관련 링크·이동·관측이 필요하다. 주소를 그대로 두고 새 언어 영역만 추가하는 경우에 전체 한국어 페이지를 새 주소로 옮기거나 일괄 이동시키지 않는다. 뒤 문장은 변경 범위를 줄이기 위한 **운영상 권고**다. [G3]

## 사실과 구분해 제안할 작업 분담표

아래는 Google이 강제하는 조직표가 아닌 **이 글에서 제공할 운영 양식**이다. 특정 제작사가 이미 권한을 갖고 있거나 어느 병원에서 아래 절차를 완료했다고 쓰지 않는다. 실제 담당자는 사이트마다 다를 수 있다.

| 확인할 일 | 기존 제작사·운영 담당에게 확인 | 추가 제작 담당이 정리 | 병원이 결정·검수할 내용 |
|---|---|---|---|
| 현재 운영 범위 | 현재 CMS·호스팅, 도메인 관리 주체, 변경 가능한 영역 | 필요한 접근과 기존·추가 영역의 작업 경계 | 요청할 언어·진료 안내·우선 페이지, 담당자 |
| 새 언어 주소 | 기존 주소와 겹치는 경로가 있는지, 해당 경로 연결 가능 여부 | 언어별 예정 주소·페이지 목록·대응표 | 유지할 한국어 주소와 안내 범위 |
| 메뉴·언어 연결 | 공통 메뉴·모바일 메뉴를 누가 수정하는지 | 새 영역의 메뉴와 언어별 연결·누락 시 대안 | 진료명·의료진·문의처 등 공식 정보의 정확성 |
| 공개·배포 | 원사이트에 반영해야 하는 항목, 반영 담당·일정 | 새 영역 공개와 링크·본문·접근 확인 항목 | 공개할 원문·번역문의 확인 상태와 공개 시점 |
| 오류 시 복구 | 원사이트 변경의 이전 상태를 누가 보관·복원하는지 | 추가 영역·연결 설정의 되돌릴 범위와 연락 방법 | 접수 창구와 문제 확인·의사결정 담당 |
| 이후 운영 | 메뉴·호스팅·공통 설정 변경 시 연락 범위 | 원문 변경이 언어별 페이지에 미치는 영향 목록 | 변경 내용을 제공·확인할 담당과 실제 지원 계약 범위 |

보안정보는 원고에 적지 않는다. 서버별 설정 명령·로그인 방법·자격증명을 본문에 넣지 않는다. 병원이 준비할 것은 관리 주체·접근 가능 여부·전달 담당 등이며, 비밀번호 공유를 공개 체크리스트의 제출 항목처럼 만들지 않는다.

## 기존 사이트 보호를 설명할 때의 경계

- `기존 한국어 사이트 유지`는 기존 본문·주소·업무 흐름을 가능한 한 보존하는 목표다. 언어 메뉴·공통 설정까지 아무것도 바꾸지 않는다는 보장이 아니다.
- 신규 언어 영역과 기존 페이지의 변경 목록을 나누고, 주요 한국어 페이지·메뉴·문의 흐름의 전후 확인 항목을 정한다. 실제 검수를 수행하지 않았다면 수행 완료 사례처럼 서술하지 않는다.
- 기존 URL까지 변경한다면 G3의 이전 계획을 적용할 사안으로 분리한다. 새 언어 영역 추가 때문에 DNS·호스팅·CMS를 전부 교체해야 한다고 단정하지 않는다.
- 공개 시점의 페이지·연결 확인과 이후 검색 색인·검색 노출·AI 인용·실제 문의는 다른 확인이다. 준비·검수·측정 결과를 섞지 않는다.

## 쓰면 안 되는 주장

- `어떤 병원 홈페이지든 기존 제작사 협조 없이 바로 추가할 수 있습니다.`
- `하위디렉토리에 만들면 원사이트에 영향이 전혀 없습니다.`
- `공식 도메인 밑에 넣으면 도메인 지수가 그대로 이전돼 무조건 상위 노출됩니다.`
- `hreflang·사이트맵만 넣으면 Google과 모든 AI에 바로 노출됩니다.`
- `다국어 페이지를 추가하려면 한국어 사이트도 새 주소로 옮겨야 합니다.`
- `블링크애드가 모든 서버·제작사·언어·수정 범위를 같은 비용과 일정으로 지원합니다.`

현재 특정 병원의 서버·권한·경로 충돌·원제작사 계약·비용·납기는 조사하지 않았다. 블링크애드의 구체적 지원 약속과 실사례는 기존 확인 자료와 현재 담당 범위에서만 쓴다.
